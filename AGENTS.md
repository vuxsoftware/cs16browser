# cs16browser

## Website upkeep

After any user-facing app change, check whether the static website in `docs/`
needs an update. Review feature claims, the getting-started steps, platform and
release status, and the app image. Update the site when those details change;
otherwise leave it as it is. Keep the website's descriptions accurate to the
current app, and do not present illustrative server data as a live result.

The site is built from `docs/src/`: `index.html` includes one file per
section from `sections/`, `style.css` imports one stylesheet per section
from `styles/`, and `site.js` is copied as is. Edit those, then run
`bun run site` to regenerate `docs/index.html`, `docs/style.css` and
`docs/site.js` (committed, because GitHub Pages serves `docs/` directly).
Never edit the generated files; `bun run site:check` fails in CI when they
are stale. The repository slug lives once, in `SITE` in
`scripts/build-site.mjs`. The app is Windows only, and every feature on the
page must be something the app really does, without restating another section.

External Counter-Strike 1.6 server browser: a Tauri 2 desktop app that fetches
the same server list the in-game browser shows (Steam's
`IGameServersService/GetServerList` Web API), queries eligible endpoints with
the GoldSrc A2S protocol over UDP, and applies heuristics that flag fake /
redirect / spam servers.

Ported from the previous two-binary layout (`cs16browser2`: CLI + separate GUI
crate + plain-Vite Svelte UI) into a single fresh Tauri + SvelteKit project.
The CLI surface was dropped; everything that survives is prod-grade.

## Architecture rules (do not break these)

**One scan pipeline.** Discovery, A2S scanning and verdict rules live in
`src-tauri/src/app.rs` and its backend modules. `gui.rs` only translates
between the webview and that pipeline. Do not add scan logic to `gui.rs`, and
do not reimplement verdict rules in TypeScript — the frontend only re-filters
what the backend already classified.

**Callback-driven, never channel-driven.** `Scanner::scan_with` takes an
`FnMut` sink on purpose: an earlier bounded-`mpsc` version deadlocked callers
that drained after awaiting the scan (observed as `[scan] 256/10000` then a
permanent hang). `AppHandle::emit` is non-blocking, which is why the GUI sink
is exactly that. Never reintroduce a channel between the scan task and the UI.

**Shared pacing gate and ban list.** `App` holds one `QueryGate` and one
`BanList` for the whole session. `start_scan` updates the config *in place*
rather than rebuilding `App`, because two gates would let a single-server
`refresh_server` re-query an endpoint the sweep had just hit — the exact thing
the per-endpoint limits (5 s gap, 3 per rolling minute, see `ratelimit.rs`)
exist to prevent. Config changes between sweeps must keep the gate and bans.
A query the user asks for on one server (Game Info open/Refresh, the row
menu) passes `interactive: true` and is checked by
`QueryGate::try_acquire_interactive`: a 2 s gap only, no window, still
recorded in the same gate. Anything that refreshes many rows (`Quick
refresh`) passes `false` and keeps the sweep's limits. Opening Game Info
sends A2S_PLAYER only (`server_players`): the sweep measured the rest of the
row and never asks for players. The dialog's Refresh, or a row never
measured, re-queries the server. Game Info retries a `recently queried`
refusal by itself once the gap has passed.

**Pacing and bans skip without sending.** A paced endpoint is reported as
`Outcome::RateLimited` and a banned one as `Outcome::Banned` — **no packet is
sent**. The scanner's contract: for such rows it sends nothing, and the caller
keeps whatever it already knew (`with_listed_fallback` / `merge_scans` in
`app.rs`). The UI must never show a paced row as dead.

**Web API filter grammar differs from the HL1 master grammar.**
`build_webapi_filter` must never contain `password\1` or `notempty\1` — the
Web API silently returns **zero rows** for unknown keys (measured; see
`masterserver.rs` docs). `no_password` is enforced client-side after A2S.

**Steam's list is capped and flooded — discovery must peel.**
`GetServerList` returns at most 10,000 rows per request, no paging, and on
appid 10 *every* request is full: redirect farms advertise 50,000+ fake
servers, so one request is a truncated slice (it held 135 real servers where
the complete list has ~770). `fetch_steam_list` therefore repeats the
request excluding the farm IPs found so far (`\nor\N\gameaddr\<ip>…`, at
most `MAX_EXCLUDED_IPS` = 250 — longer URLs get HTTP 400) until a response
comes back under the cap. Only IPs `detect::farm_ips` condemns are excluded.
The GUI always discovers with broad filters so every UI filter can act on the
same cached list without another Steam request. Its `fetch_all` budget is 16
requests. A capped answer is re-requested while it still yields new rows.

**Seed exclusions from the last discovery.** `servers.json` keeps the farm
IPs discovery condemned (`store::KnownFarm`), including ones it excluded and
so holds no rows for. A rediscovery excludes them (largest first) from its
*first* request: measured, 3 requests / ~5 s instead of 13 / ~22 s, with no
real servers lost. An excluded IP cannot be re-judged, so a seed expires
`FARM_SEED_TTL_SECS` (7 days) after its rows last condemned it; a seed whose
rows come back uncondemned is dropped. This only shapes the request, never a
verdict. The Web API allows 100,000 calls/day and Valve asks for queries to
be as infrequent as possible. Do not add requests to speed things up; the
undocumented `\or\` filter works but is not in Valve's filter grammar, so
do not rely on it. One `ureq::Agent` per `WebApi` keeps the HTTPS connection
alive across rounds.

**Farm = many ports *and* a signature, never port count alone.** Real
Latin-American hosts run 10–18 community servers per IP. `farm_ips` needs
≥10 ports plus cloned or machine-generated names, or ≥64 ports outright.
Farm verdicts are re-derived every sweep and never persisted as bans; bans
are persisted only for reasons `Reason::label_bans_persistently` accepts,
and stale bans are lifted on load. Text cues in names (URLs, "join us",
Discord invites, tab padding) are **not** detectors at all: measured, every
real server carrying one was a community promoting itself, and any soft
reason also costs a recheck query. Only an advertised *public foreign* IP is
a redirect (hard). `players>32` uses the engine cap, not `max_players`:
reserved-slot plugins make real full servers report `32/31`. Add a detector
only after measuring it against a complete listing; delete rules that never
fire or fire on real servers rather than softening them.

Do **not** group farms by /24 subnet: measured on the complete listing it
found no farm the per-IP rule misses, and it flagged 65 real Argentine
servers spread over 20 IPs of 45.235.98.0/24.

**One detector per file.** Every fake-server heuristic is a unit struct in
`src-tauri/src/detect/detectors/<name>.rs` implementing `Detector`
(`reason()` + `fires(&Subject)`), and raises exactly one `Reason`. To add one:

1. Add a variant to `Reason` in `detect/reason.rs`, list it in `Reason::ALL`
   (bump the array length), and give it `label()` and `severity()` arms (the
   compiler reports a missing arm). The label is
   persisted in ban lists, so never rename an existing one. Hard = definite
   fake (hidden, may be banned); Soft = annotation only. Default to Soft
   unless measured against the live list — text cues in names have repeatedly
   flagged real communities.
2. Create `detect/detectors/<name>.rs`: the struct, its `impl Detector`, its
   patterns/thresholds as constants beside it, and its tests (fixtures from
   `crate::detect::testing::sample`). Include real server names that must
   *not* fire.
3. Declare the module and add the struct to `detectors::ALL` in
   `detect/detectors/mod.rs`; its position is where its reason appears in an
   `Analysis`. `every_reason_has_exactly_one_detector` fails otherwise.
4. Anything needing the whole listing or transport state (farms, repeated
   names, bad headers) is computed by the caller and passed in through
   `detect::Context`; a detector only reads it. If such a verdict is Hard
   but re-derived every sweep, exclude it in `Reason::label_bans_persistently`
   (as `ServerFarm` and `BlockedName` are) so it never becomes a permanent ban.

**Query as little as possible.** On top of the pacing gate, a sweep does not
query a server that answered within `FRESH_FOR_MS` (60 s) — its row is
reused — nor one in `TimeoutBackoff` (2+ consecutive timeouts: 2 / 10 /
30 min; one timeout never counts, any answer clears it). Neither is a
verdict: reused rows keep the verdict they earned, skipped ones report
`paced`. A single-server refresh and a hard refresh bypass both.

**Discovery is metered — cache it.** Steam is queried once and written to
`cs16browser-data/servers.json`; later runs read the cache unless
`rediscover` is set. The cache is keyed on the filter string + gamedir, and a
failed fetch must not overwrite a good cache. Live A2S measurements are never
persisted (stale data must not look freshly measured).

**`bindings.ts` is generated.** tauri-specta exports it from the Rust DTOs on
every `gui::run()` (debug and release). If a Rust type changes, the frontend
build breaks until regenerated — that is the point. Never hand-edit it.

**IPC integers are u32.** Anything crossing into the webview uses `u32`, not
`usize`: JSON numbers are f64 and Specta refuses pointer-width integers.

## Frontend rules

- Svelte 5 **runes only** (`svelte.config.js` in the Kit config; components
  use `$state`/`$derived`/`$effect`, no legacy stores).
- The filter panel is remembered in `localStorage` (`cs16browser.filters`,
  validated on load). First-run defaults: every checkbox off, Anti-cheat
  `Secure`, Latency `< 100`, Name and Map empty. Name is a case-insensitive
  substring match on `hostname`; Map is the same on `map`. Every filter
  recomputes the local list without starting a scan. The game remains fixed
  to Counter-Strike for discovery; the Game list column displays each
  server's own A2S game description. The separate `/` search also matches
  hostname, map and endpoint.
- `Refresh all` sets `rediscover` and fetches Steam's complete list again.
  `Quick refresh` queries the currently visible rows without rediscovery;
  per-endpoint pacing still applies. Neither action changes filter settings.
- Settings stores the Web API key in the backend and the automatic update-check
  preference in webview `localStorage` (`cs16browser.autoUpdate`). A manual
  update check is available in Settings; installation is user initiated.
- `cs16.ts` is the backend seam: Tauri present → generated bindings; absent →
  `mock.js` (deterministic, seeded). Everything above it is runtime-agnostic.
- The list is a **virtual scroller** (`ServerList.svelte`): only viewport rows
  exist in the DOM. Row pitch is 28px (`ROW_H`); geometry constants come from
  `columns.ts`.
- Event storms are coalesced into one `store.recompute()` per animation frame
  (a 20k sweep emits ~20k events; recomputing per event is O(n² log n)).
- Chrome is a measured replica of the in-game browser (Tahoma 20px/26px, no
  border-radius, no transitions, bevel = lit top/left + dark bottom/right).
  Copy the pixels in `app.css`; do not rationalise them.
- That layout needs 1600x900 CSS px. Smaller windows keep it and zoom the
  webview (`gui::fit_zoom`, `min(0.8, w/1600, h/900)`) on every resize. The
  zoom is applied from a worker thread: `set_zoom` waits on the event loop,
  and calling it from a window-event handler froze the window.
- `style-src 'unsafe-inline'` in the CSP is required: rows are absolutely
  positioned per-index, so inline `top:` styles are load-bearing.
- The window's close box (and Alt+F4) **quits** the app; there is no tray.
  `gui::run` saves the pacing gate on `RunEvent::Exit`, so quitting mid-sweep
  does not forget which servers were just queried. The page drives the native
  window only through `nativeWindow` in `cs16.ts` (close, minimize, invisible
  resize corner), and the capability file grants exactly
  `core:window:allow-close` / `allow-minimize` / `allow-toggle-maximize` / `allow-start-dragging` /
  `allow-start-resize-dragging` for it (`core:default` is read-only).
- Connect opens `steam://connect/<ip>:<port>/` from Rust (`gui::connect`,
  via `tauri_plugin_opener::open_url`); the endpoint is re-parsed first, so
  only a plain `ip:port` reaches the URL handler. No webview URL permission.
- Tauri v2 denies IPC by default; `core:event:allow-listen` in
  `src-tauri/capabilities/default.json` is what makes `events.scan.listen`
  work. A rejected listener must surface as an error, never a silent blank list.

## Environment

- The Steam Web API key comes **only** from the Settings dialog (the title
  bar's gear), stored in `cs16browser-data/settings.json`. Nothing reads
  `STEAM_API_KEY` or a `.env` any more. Without a key nothing is discovered —
  no Steam request, no cached list, no HL1 fallback — and the page opens
  Settings on start. The key never crosses back into the webview;
  `get_settings` returns only a masked hint, and `open_api_key_page` opens
  the one fixed Steam URL (no arbitrary-URL permission).
- `CS16BROWSER_STATE` / `CS16BROWSER_DATA` — override the state/cache paths.
- `CS16BROWSER_API_BASE` — point the Web API client at a stub (tests only).

## Data files (runtime, not committed)

- `cs16browser-state.json` — history + pacing gate + bans + recheck queue,
  written atomically (tmp + rename). Tolerant load: corrupt ⇒ empty, never
  fatal.
- `cs16browser-data/servers.json` — the discovery cache (raw Steam rows only).
- `cs16browser-data/settings.json` — the Web API key saved from Settings.
- All of these are in `src-tauri/.taurignore`: `tauri dev` rebuilds and
  relaunches on any change under `src-tauri/`, and the app writes them there.

## Wire-protocol notes

- `addr` from the Web API is the **query** port (what A2S answers on), not
  always the game port.
- GoldSrc info replies come in three shapes — `0x49` (Source layout), `0x6D`
  (GoldSrc detailed: an optional mod block, then VAC, then bots; no game
  version), `0x43` (deprecated, no bots). The
  field order differs between them; `parse_info` dispatches on the header.
- Some servers require a challenge round-trip before answering; the challenge
  is **appended to the query string** for INFO (`…Query\0<challenge>`), but
  replaces the placeholder for PLAYER.
- Shared pooled sockets are safe because answers are matched by source
  address (`recv_from_peer`); never accept a datagram from a different peer.
